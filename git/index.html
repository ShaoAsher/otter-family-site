      01 · 仓库状态

      仓库处在什么状态，
      小獭的脸上就写着。

      工作区（Working Tree）有改动时它专注，撞上合并冲突（Merge Conflict）它紧张，同步完成它放松。背景环境层、小獭表情、状态栏读的是同一份状态；往下滚动，本页背景也会跟着变。

      1. Working Tree · 有改动

        改了 12 个文件，先看清再提交

        待提交的文件按目录列出，选中一个，右边就是左右对齐的对比。只想先交其中一处？点改动块上的「暂存此块」。

      2. Merge Conflict · 冲突

        撞上冲突，横幅会一直提醒

        冲突文件排在最前面并标红。只有一边改过的块可以自动解决，两边都改过的逐块挑选，也能打开三方合并对照着改。

      3. AI Agent · 小獭协助

        交给小獭，它先列出步骤

        「帮我写提交说明并提交」：小獭暂存、起草说明，到推送这一步先停下，出一张确认卡，写清会改动什么、风险等级多高。

      4. In Sync · 已同步

        推送完成，历史里记得清清楚楚

        每个分支一条泳道，本地和远程停在哪一目了然。顶部统计栏记录这个仓库一共提交了多少次、今天提交了几次。

      02 · 结果反馈

      每一次提交，
      都有人替你记着。

      提交、推送、拉取的进度弹窗在完成后原地切换成结果页：进行中是拖着行李出门，完成了是抵达和欢呼，下一步按钮就在手边。

      • 提交后一键推送有上游分支时，结果页的主按钮就是「推送」；没有上游时可以直接撤销这次提交。
      • 里程碑会被记住第 1 次、每第 100 次提交，小獭会换上庆祝的表情；新分支首次推送、一次推上 10 个以上提交，也各有专属的一刻。
      • 小事不打断你「已是最新」「已暂存」这类结果只在状态栏提示一句，几秒后自动消失；拉取前自动贮藏、拉完放回，也不会多弹一个窗。

      03 · 专业功能

      专业功能，
      用它们本来的名字。

      界面里写的就是 Git 的术语：Commit、Stash、Rebase、Cherry-pick……学到的每个词都能在别处用上。每个功能旁边，小獭都有一句话。

      01 · Commit Graph · 提交图谱

      按泳道看清分叉与合并

      每个分支一条泳道。本地 HEAD 停在哪、远程（origin）走到哪、谁合进了谁，图上都标着。点开一条提交，右侧就是这次改了哪些文件。

      • 按提交说明、作者或哈希搜索，⌘3 直接打开
      • 右键提交：拣选、回滚、变基到这里、创建补丁、打标签

      第 1,299 次提交，每一次我都记着。

      02 · Side-by-side Diff · Hunk Staging

      删除标红，新增标绿，按块暂存

      新旧两栏按行对齐，一边多出几行，另一边就空出几行，后面的代码不会整段错位。一个文件改了三处，可以只暂存（stage）其中一块（hunk）。

      • 暂存文件、暂存此块、丢弃此块，按钮都在改动块的标题栏上
      • 图片、视频、PDF 也能全屏对比；也可以换成外部 diff 工具

      只交这一块？没问题，其他的先留着。

      03 · 3-way Merge · 三方合并

      冲突逐块解决，不再对着 <<<<<<< 发呆

      拉取或合并撞上冲突，冲突文件排在列表最前面。只有一边改过的块点「自动解决」，两边都改过的「逐块解决」，想看全貌就打开三方合并：base、ours、theirs 并排对照。

      • 合并没完成时，顶部横幅一直提醒，改完点「去提交」
      • 「中止合并」回到合并前；也可以让小獭先出一版方案

      别慌……其实我比你还紧张。我们一块一块来。

      更多 Git 操作

      命令行能做的，
      这里都有界面。

      每个操作执行前都能看到将要运行的 git 命令；危险的那几个（强制推送、硬重置、丢弃改动）每次单独确认。

      Stash

      贮藏

      改到一半要切分支？先把工作区收进贮藏，回来再取（apply / pop）。拉取被未提交改动挡住时，会自动贮藏、拉完放回。

      先帮你收进小箱子，拉完再放回来。

      Interactive Rebase

      交互式变基

      把一串零碎提交整理干净：重排、合并（squash）、改说明、丢弃，拖动列表即可，执行前能看到将运行的命令。

      历史整理好了，干干净净。

      Cherry-pick

      拣选

      只想要别的分支上的某一次提交？右键它，拣到当前分支；冲突时可以继续、跳过或中止。

      这一抽，正好是你要的那张。

      Revert · Reset

      回滚与重置

      Revert 生成一次反向提交，安全撤回已推送的改动；Reset 回到指定提交，软、混合、硬三种模式写清后果。

      硬重置之前，我会再问你一次。

      Reflog

      引用日志

      HEAD 去过的每一个位置都在这里。误删分支、重置过头，从 reflog 找回那次提交，一键恢复。

      丢了的提交，多半还能找回来。

      Bisect

      二分查错

      标一个正常的提交、一个出错的提交，git bisect 对半缩小范围，几步定位引入问题的那一次。

      让我想想……就是这一次！

      Tag

      标签

      给发版的提交打上轻量或附注标签，推送时可以带上全部标签。

      打个标签，留个纪念。

      File History

      文件历史

      一个文件被谁、在哪次提交里改过，按时间排开，点开任意一次就是当时的对比。

      这一行是三周前改的，我翻到了。

      Worktree · Submodule

      工作树与子模块

      同一个仓库同时检出多个分支；子模块的添加、更新、移除都在一处管理。

      两个分支并排放着，互不打扰。

      Git-flow · LFS

      分支流程与大文件

      功能、发布、热修复分支的名字和起点自动填好；大文件交给 Git LFS 跟踪。

      功能分支从 develop 出发，我替你填好了。

      Pull Request

      拉取请求

      分支推送后直接创建 PR，支持 GitHub、Gitee、GitLab、Bitbucket。

      推上去了，叫上队友一起看看。

      Auto Fetch · Tray

      后台获取与菜单栏

      按设定间隔在后台 fetch；不开主窗口，菜单栏也能看到可拉取、未推送的数量并一键同步。

      远程有 3 个新提交，排好队了。

      浅色 / 深色

      两套主题，各自精修。

      跟随系统，或者手动指定，切换不用重启。界面语言支持中文和 English。

      04 · 小獭 AI 助手

      动手之前，先确认。

      小獭在窗口右侧。看状态、拉取、推送、暂存这些短指令不配模型也能用；配上模型后，写提交说明、起草 PR 描述、把「提交并推送」拆成几步完成，都可以交给它。

      Steps

      每一步都摆出来

      多步任务显示为步骤卡：已完成、进行中、待执行一眼分清，思考过程可以展开查看。

      Confirm · L1–L3

      写操作先出确认卡

      确认卡列出涉及的文件、目标分支和领先落后数，并标注风险等级。强制推送、硬重置、丢弃改动每次单独确认。

      Memory

      会话按仓库隔离

      每个仓库有自己的对话记录和仓库记忆，提交约定、分支习惯会自动带上。仓库里有 AGENTS.md 时也会读取。

      Model

      模型由你自己接入

      填写接口地址、API Key 和模型名称，兼容 OpenAI 接口的服务都可以使用。用量按模型记录，随时可查。

      08 · 常见问题

      你可能想问的

      要花钱吗？

      不用。没有内购、订阅或专业版。小獭使用的模型由你自己接入，费用直接与模型服务商结算，App 不经手。

      小獭会擅自改动我的仓库吗？

      出厂为「默认」档：日常操作直接执行，拉取、推送等会先确认，不可撤销的操作每次单独确认。也可以调到「询问」或「完全信任」。冲突没解决完的提交，任何一档都会拦下。

      我的代码会被上传吗？

      仓库读写都在本机完成，使用的是你安装的 git。未配置模型时，小獭的短指令也在本机执行。配置模型并与它对话时，相关内容会发送到你填写的接口地址。

      支持 Windows 和 Intel Mac 吗？

      Windows 10 / 11（x64）提供预览版，欢迎反馈问题。Intel 芯片的 Mac 暂不支持。

      需要先安装 git 吗？

      需要。水獭 Git 调用的是本机的 git。装了多个版本时，可以在设置里指定使用哪一个。

      官网的在线试用和 App 一样吗？

      界面、交互和动效与 App 3.0 一致，用来快速了解操作方式；数据是演示数据，不会读取你的仓库。完整功能请下载 App 使用。

      小獭的表情会不会打扰我干活？

      不会。只有提交、推送、拉取、合并这类值得记住的时刻才会弹结果页，几秒后自己收起；「已是最新」「已暂存」这类小事只在状态栏说一句。系统开了「减弱动态效果」时，小獭换成静帧。

      我对 Git 不熟，能用吗？

      能。界面上写的是 Git 的标准术语，按钮旁边有说明，执行前能看到将要运行的命令；不会的操作可以直接用大白话问小獭，它会先列出步骤再请你确认。

      为什么叫水獭？

      水獭睡觉时会牵着同伴的手，避免彼此走散。分支一多也容易走散，总得有谁帮你盯着。
